# Web 与多端技术

## 为什么保留两种 Web 主栈

社区与资料偏重内容、SSR 和编辑体验，由 Nuxt / Vue 承担；商城偏重交互、收藏和主题预览，由 Next.js / React 承担。两者都能做这些业务，这个分工主要服务于清晰的学习场景，不表示框架能力存在绝对边界。

Nuxt 与 Next.js 都有服务端执行能力。学习重点是识别代码在哪运行、什么能进入浏览器、SSR 缓存是否会泄漏用户数据，以及会话如何安全处理。业务账本仍在 Grail，不能因为 Server Actions 方便就复制扣款规则。

待做实验：服务端渲染公开资料，登录后展示个人收藏；验证缓存不会混入另一用户的数据；模拟身份服务不可用，仍能阅读公开内容。

## Flutter 的复用边界

Flutter 共享 Dart 业务状态和组件，但系统登录、安全存储、文件访问、通知、窗口与签名仍有平台差异。支持平台列表只说明框架能力，不等于 Magic 已在全部平台交付。

待做实验：Android 和可用 iOS 环境分别完成登录返回与主题下载；在 Windows 验证离线资料缓存；中断下载后检查临时文件和重试。版本以官方 stable 渠道与实际构建结果为准。

## 小程序不是普通浏览器

Taro 让 React 开发方式适配小程序，但组件、路由、网络域名和登录均受平台环境影响。共享请求模型与设计令牌是可行起点，不能直接复用依赖 DOM 的整个 Web 组件库。

待做实验：在开发工具和真机运行同一阅读与收藏流程，确认登录绑定、下载限制和错误提示。真实平台凭据与发布是后续条件，不属于 M0。

## 共享与版本兼容

从 OpenAPI 生成 TypeScript 和 Dart SDK，保持用户 ID、时间和错误码一致。主题通过资源清单声明适用客户端版本，不能把一次 Web 更新当作全部客户端已更新。

正式范围见 [客户端设计](../design/clients.md)。官方资料：[Nuxt](https://nuxt.com/docs)、[Next.js](https://nextjs.org/docs)、[Flutter](https://docs.flutter.dev/)、[Taro](https://docs.taro.zone/docs/)。

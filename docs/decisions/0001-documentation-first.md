# ADR-0001：文档优先的 M0

日期：2026-10-07。状态：accepted。依据：P-007。

## 背景

Magic 是长期、多技术栈项目，用户将 M0 明确调整为详细架构、技术文档、开发规范及学习手册。提前建立四种语言的空工程不能证明业务可用，也会增加维护负担。

## 决定

M0 交付 Markdown 正本、GitBook 目录、治理登记、设计、学习章节、开发流程和可运行文档门禁。成熟 Markdown／YAML 解析工具承担语法处理，项目脚本只校验本仓库约束。

只建立 Node 文档工程，产品服务、应用与 Compose 实现移到对应阶段。在线 GitBook 接入独立授权，本地 Markdown 始终可阅读。

## 替代方案与后果

一次搭建全部服务能较早展示技术数量，但会使空项目与真实交付混淆。使用单个巨大 README 起步更省文件，却不利于规范与学习章节独立演进。

采用分层文档需要维护导航和正本，因此增加自动登记／链接检查。新阶段开始时清理过程文件，防止无限增加重复文档。

复查条件：文档数量、导航或构建成本开始明显阻碍阅读时，调整结构或评估专门站点工具。

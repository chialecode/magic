# ADR-0003：阶段提交与渐进启用分支保护

日期：2026-10-07。状态：accepted。依据：P-009 和当前远端为空的实际检查。

## 决定

根提交只含空 README；M0 和后续阶段各有独立阶段提交。未推送修复 amend，已共享历史默认保留，main 通过 squash 保持每阶段一个提交。push、PR、合并分别遵守授权范围。

空仓库先应用禁止删除、强推和非线性历史的基础规则。首次 PR 实际产出成功检查后更新同一 ruleset，增加 PR 和绑定 GitHub Actions App 的必需状态。

## 取舍

立即要求从未产出的检查可能锁住初始化；永久管理员绕过会削弱日常保护。因此使用有明确收敛步骤的初始化配置，并如实记录此期间普通快进直推尚未被技术禁止。

当前单人维护，强制独立批准人数为 0；CODEOWNERS 表示责任，无常驻绕过者。后来增加协作者时可以调整审批人数。

最终保护接线、外部 CI 和合并分别验证，不以配置文件存在代替远端生效。保护只能在有授权和明确理由时修改，不能因失败检查自动降级。

# 领域模型与数据一致性

状态：目标模型，迁移脚本与数据库尚未实现。字段表描述语义，不冻结具体 ORM 或 SQL 类型。

## 1. 数据归属

| 领域 | 核心实体 | 核心关系与约束 |
| --- | --- | --- |
| 身份 | Identity、ExternalIdentity | 身份服务产生稳定 subject；外部账号绑定必须验证控制权，不按可修改昵称自动合并 |
| Magic | Profile、Circle、Membership、Post、Comment、Report | 帖子属于分区或圈子；成员角色限定圈子；审核状态控制可见性 |
| Akasha | Work、Entity、Timeline、Revision、Citation、Relation、ImportJob | 修订属于词条；实体与作品／世界线关联；引用标注来源和位置 |
| Grail | CreditAccount、LedgerEntry、Product、SKU、Inventory、Order、OrderItem、Entitlement、Refund | 流水不可覆盖；订单快照商品条件；权益可撤销但保留来源 |
| Imaginary | Asset、AssetVersion、Manifest、ProcessingJob、UploadSession | 资源版本不可原地变更；发布版本关联摘要与内容清单 |

外部实体 ID 不建立跨库外键。服务内用数据库外键和唯一约束维护关系；跨域引用通过接口验证并接受目标删除／失效的显式状态。

公共约定：ID 为不透明字符串；时间在持久化与 API 中使用 UTC；用户界面按用户时区显示。金额类业务未来另行设计，首期只有整数积分，不用浮点数。对 JavaScript 不安全的整数使用十进制字符串传输。

## 2. 社区与资料

帖子状态建议为 `draft → pending → published → hidden/deleted`，状态变化记录操作者、原因和时间。作者编辑已发布内容时是否重新审核由内容规则决定，不允许通过编辑绕过发布审核。

词条实体 ID 与修订 ID 分开；同一实体可以有多个版本的事实和来源。发布指针指向已审核的不可变修订；回滚是重新指向历史修订并追加审计，不删除后续历史。

使用版本号或等价并发控制防止最后写入静默覆盖他人编辑，冲突返回可比较的差异。导入任务以批次和来源对象去重，支持取消、失败重试和隔离待审核内容。

## 3. 积分与兑换不变量

1. 每个积分账户有一个权威余额与不可覆盖流水；余额变化和流水新增在同一事务中提交。
2. 余额和有限库存不得为负。库存用明确的无限模式表示无限供给，不混用负数库存。
3. 每条流水含账户、增减值、原因、关联订单／奖励业务键和幂等来源；冲正新增关联流水，不改历史金额。
4. 订单保存商品名称、积分价格、SKU、资源版本和使用范围快照；以后改价不能改变历史订单。
5. `actor + operation + idempotency_key` 唯一，保存请求摘要与结果引用；同键不同请求拒绝，同键同请求返回原结果。处理中请求应返回可重试状态，不再次执行。
6. 奖励按业务键唯一，例如一次投稿奖励，不仅按消息 ID 去重。重新发布消息不能绕过奖励上限。
7. 永久内容默认同一用户同一 SKU 仅持有一份有效权益；重复购买策略在商品定义中固定，不能静默重复扣分。

### 兑换事务顺序

校验请求和幂等记录 → 按稳定顺序锁定账户与库存 → 校验已持有权益及资源发布条件 → 条件扣减库存与余额 → 新增订单、流水和权益 → 写出必要 Outbox → 保存幂等结果 → 提交。

数据库约束和原子条件更新是并发正确性的最后保障；缓存锁不能作为唯一保障。事务失败整体回滚，瞬时死锁仅在有幂等保护且有限次数的情况下重试。

资源版本发布条件以先前验证、不可变资源引用和商品上架状态约束，避免在持有数据库锁时进行长时间网络调用。若资源后来撤下，已完成订单由退款规则处理。

### 状态与退款

首期订单同步兑换，业务结果为成功或失败；数据库中完整成功订单状态为 `fulfilled`。技术失败的请求记录不能伪装成已扣款订单。

运营退款只针对已完成订单，由唯一退款请求在同一事务中冲正积分并撤销对应权益，订单转为 `refunded`。限量库存是否恢复由商品快照规则决定；退款请求重复到达返回原结果。

暂不引入支付待付、支付回调和外部对账状态。将来接入真实支付必须新增专门设计，不能把演示积分接口直接当支付接口。

## 4. 资源与权益

资源版本状态为 `uploaded → quarantined → processing → review → published`，失败或拒绝保留原因；撤下版本保留记录并禁止新签发下载凭证。

资源清单至少包含资源 ID、版本、类型、文件列表、摘要、大小、兼容客户端范围、授权说明及预览信息。文件发布后不可替换原对象内容，修正通过新版本完成。

权益记录包含用户、SKU／订单项、资源许可范围、生效与失效时间、撤销原因。客户端缓存只是体验层，服务端仍以当前权益为准。已经离线下载的静态文件不承诺远程销毁。

## 5. 迁移与删除

每个服务独立维护有序迁移。上线优先兼容扩展、迁移数据、切换使用方、最后移除旧字段；记录可回滚部分与需要备份恢复的部分。

删除账号需要分别处理个人资料、公开内容署名、资源访问和账本关联。匿名化规则在账号删除功能实施前细化，不能直接级联删除审计与交易流水。

测试使用合成用户和样本，不以生产数据验证迁移。备份恢复必须同时核对数据库里的资源引用与对象文件。

# API、事件与资源契约

状态：目标协议约定，尚未生成实际 OpenAPI 文件或 SDK。接口示例用于解释责任边界。

## 1. HTTP 约定

外部 API 使用 `/api/v1/<domain>/...`；版本表示需要独立兼容的接口主版本，不随每次发布递增。健康检查与监控端点分别暴露，避免将内部指标公开到用户入口。

OpenAPI 为 HTTP 契约正本，资源包和事件使用 JSON Schema。写入接口声明身份、权限、幂等、输入限制及错误；客户端 SDK 从契约生成，生成命令和差异检查应随服务实现一起交付。

| 类型 | 约定 |
| --- | --- |
| 标识符 | 不透明字符串，不通过递增 ID 推断权限 |
| 时间 | RFC 3339 UTC，客户端负责展示时区 |
| 分页 | 列表优先游标分页；排序键稳定且含唯一 ID；游标不可作为授权证明 |
| 错误 | HTTP 状态 + 稳定业务 code + 用户可理解的说明 + requestId；不返回内部堆栈 |
| 并发编辑 | 资源版本或 ETag + 条件请求，冲突明确返回 |
| 幂等 | 对兑换、奖励与退款等写入定义键作用域、保留策略和重复请求语义 |
| 追踪 | W3C Trace Context；服务端生成或校验请求 ID，不信任无限长度外部字段 |

示例错误形状：

```json
{
  "type": "about:blank",
  "title": "积分不足",
  "status": 409,
  "code": "GRAIL_INSUFFICIENT_CREDIT",
  "requestId": "example-request-id"
}
```

敏感资源不存在与无权访问的返回策略保持一致，防止枚举。搜索和批量接口也必须逐项满足可见性；后台角色不能由客户端任意声明。

## 2. 跨域接口边界

| 提供方 | 代表用例 | 关键保证 |
| --- | --- | --- |
| Magic | 查询帖子、提交审核、关注圈子 | 可见性、编辑冲突、审核审计 |
| Akasha | 查询实体摘要、提交修订、导入状态 | 来源可追踪、版本不可变、失败可恢复 |
| Grail | 创建兑换、查询订单、校验权益、运营退款 | 事务、幂等、权限及撤销效果 |
| Imaginary | 创建上传会话、发布资源版本、请求下载凭证 | 输入限额、不可变版本、在线权益校验 |

服务间调用采用独立身份和明确 audience。公共客户端不能直接调用运营退款、资源审核或内部奖励接口。

## 3. 可靠事件

事件信封包含 `eventId`、`eventType`、`schemaVersion`、`occurredAt`、`producer`、`aggregateId`、`correlationId` 与 `payload`。不在事件中传播访问令牌或无关个人数据。

初步事件包括帖子奖励资格达成、订单完成、权益撤销和资源发布。业务事件描述已经发生的事实，不向消费方暴露生产方的数据库表结构。

- 生产方将状态与 Outbox 一起提交；发布成功前任务可以重试。
- 消费方在本地事务内登记 Inbox／去重键并修改业务状态，之后才确认消息。
- 至少一次投递可能重复、乱序和延迟；依赖顺序的业务检查聚合版本，缺失事件可补偿或重读权威状态。
- 失败记录包含分类、重试次数和下一次时间；超过限制进入待处理队列，可审计重放，不静默丢弃。
- Outbox 不表示已经有 MQ；先采用明确的投递适配器，MQ 进入部署时保留相同幂等约定。

新增可选字段保持兼容；删除或改变语义使用新 schemaVersion，并定义双版本消费窗口。消费者契约测试随变更更新。

## 4. 资源格式

主题使用声明式 JSON 和静态资源，不能因下载资源包而执行任意 JS 或本机命令。表情清单包含稳定标识、文件摘要、尺寸及适用场景。

校验 JSON Schema、文件类型与实际内容、单文件和总包大小、解压后大小、路径穿越与重复路径。处理失败留在隔离区；未发布文件不进入公开缓存。摘要验证完整性，发布者信任和用户权益分别校验。

## 5. 兼容与验证

后续交付应覆盖消费者生成检查、破坏性契约差异、未授权访问、重复写入、事件重复和乱序、旧版本资源清单及不支持客户端的错误提示。

文档示例不充当真实凭据或真实服务地址；API 未实现时不生成虚假的成功调用证据。

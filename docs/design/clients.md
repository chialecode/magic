# 客户端范围与共享设计

状态：规划。正式支持的平台以实际构建、安装和测试记录为准。

## 1. 分工

| 客户端 | 主栈建议 | 主要场景 |
| --- | --- | --- |
| 社区与资料 Web | Nuxt / Vue / TypeScript | 公开检索、SSR、资料引用、讨论、编辑与社区管理 |
| 商城 Web | Next.js / React / TypeScript | 商品、兑换、收藏、资源预览与商城管理 |
| 移动端 | Flutter / Dart | Android 与 iOS 日常浏览、发帖、通知、主题与收藏 |
| 微信小程序 | Taro / React / TypeScript | 轻量阅读、搜索、分享及个人收藏 |
| 桌面端 | Flutter，后续按专题评估其他方案 | Windows 优先，离线阅读、资源与主题管理；macOS / Linux 分别验证 |

多端功能不要求完全同构。平台没有对应能力时，返回清晰状态和支持范围，不显示无法完成的操作。

## 2. Web 边界

Nuxt 与 Next.js 的服务器层用于 SSR、会话和必要的请求组合，核心业务仍在领域后端。禁止把订单扣款或词条审核规则复制到 Server Actions 和浏览器。

不同应用使用统一身份与设计令牌，但保留独立应用会话。跨应用跳转只允许可信回调地址，避免开放重定向。

## 3. 共享能力

共享色彩、字体尺度、间距、图标、主题令牌、文案键和资源清单。Vue、React 与 Flutter 分别实现组件；API 客户端从契约生成，不手工维护多份易漂移请求模型。

统一加载、空状态、无权限、网络失败、内容撤下、版本不兼容和重新登录体验。键盘操作、焦点、可读对比度、减少动画和剧透提示进入对应界面的验收。

## 4. 本地内容与登录

离线缓存记录资源版本、完整性摘要与更新时间。内容刷新失败保留可用的旧版本并提示状态；缓存无法证明当前在线权益。安全存储与普通资源缓存分离。

移动端采用系统浏览器 PKCE；小程序由后端兑换和校验平台凭证，再绑定统一身份。iOS 签名、应用商店和小程序发布各有外部条件，服务端部署脚本不自动完成平台审核。

## 5. 进入实现前的验证

首批 Flutter 原型验证登录返回、安全存储、深链接、资源下载与 Android / iOS 构建；桌面额外验证文件权限和更新机制。小程序验证登录、域名配置、网络限制与真实设备行为。

选择组件库时记录维护、许可证、可访问性、SSR 兼容和主题扩展证据。当前不为了齐全同时引入多套 UI 库。

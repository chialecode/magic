# 编码、契约与数据规范

状态：当前开发规则；语言工具在相应项目建立时接入，不凭文档宣称检查已存在。

## 1. 通用约定

- 类型、函数和文件名准确表达业务，避免难以搜索的缩写；对外字段、错误码和事件名保持稳定。
- 模块暴露必要接口，不通过跨目录内部导入绕过边界；共享代码必须有实际使用者和清晰责任。
- 配置与秘密分离，启动时验证必需配置；不同环境不靠隐藏硬编码切换。
- 明确错误类型和处理责任；日志记录上下文及关联 ID，不重复输出敏感请求正文。
- I/O 调用有超时、取消和资源释放；自动重试只用于具备幂等性或天然安全的操作。
- 依赖固定版本并提交锁文件；升级说明包含兼容影响、许可证变化和相关回归结果。

## 2. 各语言惯例

| 语言 | 默认规范 | 重点 |
| --- | --- | --- |
| Java | Java LTS、Spotless、JUnit、Gradle Wrapper | 构造器注入、显式事务边界、DTO 与持久化模型分工、不吞异常 |
| Go | gofmt、go vet、golangci-lint、原生测试 | context 贯穿调用、错误包装、goroutine 生命周期、接口由使用方需要决定 |
| Python | 类型标注、Ruff、mypy、pytest、uv | 输入模型校验、异步中避免阻塞、数据导入任务可恢复、禁止隐式全局状态 |
| Rust | rustfmt、Clippy、Cargo test | 明确 Result、受限并发、流式处理、不对外部输入随意 unwrap 或 panic |
| TypeScript | strict、ESLint、格式化、Vitest | 区分浏览器与服务端、禁止秘密进入 bundle、必要时运行时校验 |
| Dart | formatter、analyze、flutter test | 异步取消、状态清晰、平台适配隔离、资源及时释放 |

## 3. 数据与安全

数据和交易规则以 [领域模型](../design/domain-model.md)为准。数据库迁移必须可重复验证，不能手工改本地库后遗漏迁移文件；历史流水不通过更新覆盖。

服务端校验身份、资源归属及操作权限；输入、文件和解压内容都有边界。资源清单、搜索结果和批量查询不能成为绕过权限的旁路。

真实用户数据、密钥、平台签名和带凭据日志不得进入 Git。示例使用明显的占位值或合成数据；不要在错误输出中打印秘密。素材授权、仓库许可和依赖许可分别管理。

## 4. 测试与注释

测试针对真实约束和风险，包括边界、故障、幂等、并发与恢复，不机械镜像实现。关键事务使用真实数据库集成测试；多端兼容需要契约与目标平台验证。

注释解释不明显的业务原因、并发假设或外部限制。临时 workaround 标注上游缺陷 ID、触发条件、版本范围和删除标准，不能留下无来源的永久魔法判断。

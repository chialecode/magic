# 文档治理

## 1. 正本与状态

产品原则记录用户确认；需求定义业务；设计定义边界和契约；开发规则定义工作方法；ADR 解释重要决定；学习手册解释原理与实验；交付文件记录实际结果；用户事项集中在根目录待办。

所有自有 Markdown 在 [登记表](document-registry.json)登记 `path`、`kind`、`status`、`scope` 和 `reviewed`。状态为 `active`、`draft`、`reference` 或 `superseded`；文档 active 只表示规则或入口生效，不表示产品已经实现。替代文档记录 `supersededBy`。

## 2. 导航与书籍目录

`docs/README.md` 提供任务入口，`docs/SUMMARY.md` 提供 GitBook 章节目录。新增和迁移文件必须同步登记与导航，保留唯一正本。模板可重复使用，但实例不能被登记为已经完成的业务。

链接使用仓库相对路径，标题锚点采用 GitHub 可识别形式；链接不得逃出仓库。明确区分计划目录与当前存在的文件，不给未创建目标制作假链接。

## 3. 变更与冲突

当前任务有效指示优先于历史约定；同步修订受影响正本。代码表示实际行为，需求表示应有行为，两者冲突时查明缺陷或过期设计，不能自动用一方覆盖另一方。

小型纠错无需新增提案。业务语义、数据归属、公共接口或主框架变化记录 ADR／变更提案及验收更新。决定状态与用户授权分开，不能由一篇文档自动产生外部操作许可。

## 4. 长期维护

需求、验收和缺陷编号不复用，修改历史背景通过 Git 和 ADR 追踪。阶段计划和报告只保留当前版本；下一阶段先提炼仍有效结论，再更新过程文件。

学习手册记录当前结论及已知边界；版本过期时链接新的复核证据。上游缺陷保留受影响和已修复版本，不能为了文档整洁删除仍有用的复现知识。

## 5. 质量与证据

文档修改运行统一检查，保证格式、登记、相对链接和必要配置一致。检查不会验证语义真实性、外部网站长期可用、Mermaid 渲染或产品功能；这些由实际验证记录说明。

证据标记日期、环境、命令、结果和未执行项，不保存秘密或个人机器路径。源快照仅证明查询时观察到的数据，不代表固定版本承诺。
